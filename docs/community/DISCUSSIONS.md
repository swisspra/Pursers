# GitHub Discussions

[GitHub Discussions](https://github.com/swisspra/Pursers/discussions) is the
public place for questions, proposals, and examples that benefit from community
conversation. It is not a channel for credentials, private board records,
security-sensitive reports, or identifying local paths.

## Choose a category

- **Announcements** — maintainer-authored release and project updates. Follow
  this category for public milestones; start a separate Q&A or Idea discussion
  when you want to respond with a new topic.
- **Q&A** — focused questions about installation, configuration, documented
  behavior, and supported workflows. Mark a helpful response as the answer when
  the question is resolved.
- **Ideas** — problems, use cases, and desired outcomes that could influence
  the [roadmap](../ROADMAP.md). An Idea is a proposal, not a commitment.
- **Show and tell** — working Pursers setups, integrations, and lessons that
  others can reuse. Sanitize screenshots and logs before posting.

Bug reports and security-sensitive disclosures need different handling. Do not
post an exploit, credential, or private board content in a public discussion.

## Response expectations

Pursers is a single-maintainer beta, so Discussions have no response-time SLA.
Replies are best effort, and release safety or security work may take priority.
Community members are welcome to help with reproducible, evidence-backed
answers. A clear title, one bounded question or proposal, the Pursers version,
and sanitized observations make a useful response more likely.

If a topic has no immediate reply, that does not mean it has been accepted,
rejected, or scheduled. Avoid reposting the same topic; add material evidence
to the original discussion instead.

## From discussion to board work

Discussions collect public context. The Pursers board controls implementation
work and its review trail. They are related, but they are not the same queue:

1. A community member opens a Q&A, Idea, or Show and tell discussion.
2. The maintainer clarifies scope, impact, and supporting evidence in public.
3. If concrete repository work is warranted, the maintainer creates a bounded
   board ticket with its own allowed files, acceptance checks, and reviewer.
4. Shipping still requires implementation, independent review, and the normal
   release gates. The roadmap changes only when that state is verified.

A discussion does not automatically create a ticket or reserve a release. The
maintainer may link public outcomes between the two systems without exposing
private board data or internal ticket identifiers.
