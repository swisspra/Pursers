# Pursers v5.0.0b1 release notes

## Beta prerelease

Pursers 5.0.0b1 is a beta prerelease for evaluation, not a stable release. It
is designed for one owner on one machine. Do not expose it as a remote service
or use it on a shared or untrusted machine: every local process and operating
system user is inside its trust boundary.

## What you get

- `pursers`, the dependency-only installer for the standard Python packages.
- `pursers-central`, the local MCP coordination service backed by SQLite.
- `pursers-client`, the asynchronous Python client used by Pursers tools.
- `pursers-personal`, the Personal Preview command and read-only MCP Apps
  dashboard.
- `pursers-personal-import`, the copy-only utility for deliberate migration
  from a frozen legacy snapshot.
- `pursers-wait-bridge`, the event-wait bridge and `pursers-door`
  administration command.
- `pursers-aionui`, a separately installed AionUi extension archive with
  Worker and Reviewer presets plus a Pursers settings tab.

## What changed

- Project-registry entries can declare an exact, board-scoped HTTPS repository
  URL for routing work. Routing is rejected before work is claimed or verified
  when the repository URL, checkout, board, or operator-ownership mapping is
  unsafe. Registry administration also uses compare-and-set updates.
- Fleet Dashboard security handling was tightened without changing redaction
  output: sensitive-key redaction avoids polynomial regular-expression
  backtracking, successful Central staging no longer logs its staged wheel
  path, mock package-index routing compares parsed hostnames, and script-tag
  extraction also handles upper-case tags.

## Install and run

Install the standard package set and confirm the Personal command is present:

```bash
pip install pursers
pursers-personal --version
```

To try the Personal command without installing it permanently:

```bash
uvx pursers-personal --version
```

All six Python distributions require Python 3.11 or newer. The `pursers` and
`pursers-personal` metadata explicitly list Python 3.11 through 3.14, and the
Personal package currently classifies macOS as its operating system.

For local configuration from a source checkout, run:

```bash
python tools/fleet-dashboard/fleet_dashboard.py
```

Then open `http://127.0.0.1:8899` and choose **Config**.

Same-machine Central connections use plain HTTP on loopback, normally
`http://127.0.0.1:8766/mcp`. Central data remains local in SQLite. Tokens are
bound to the exact Central URL, including its scheme, host, port, and path.

## Upgrading or starting fresh

To upgrade from a 5.0.0a release:

```bash
pip install --upgrade pursers
```

If an older setup used an HTTPS loopback URL, changing it to the current HTTP
loopback endpoint also requires new tokens because the URL is part of each
token's binding.

For a first installation, use the quickstart above. Installing Pursers does
not modify an existing `onboard-memory-mcp` 4.0.4 installation. Moving legacy
records is a separate, deliberate, one-way snapshot import with
`pursers-personal-import`, not an automatic synchronization.

## Known limitations

- This beta is limited to a single owner on a trusted machine; multi-user
  admission and remote deployment are not supported product boundaries.
- The Personal Preview metadata currently targets macOS.
- The repository does not yet make a supported MCP Apps host claim. Its
  dashboard is read-only, and other changes are made through agent chat.
- Push wake-up is optional. Polling remains the default fallback.
- Storage is local SQLite; cloud storage is roadmap work.
- The AionUi integration documents limitations in version 2.2.1 around MCP
  server injection, assistant preset selection, and elicitation forms.
