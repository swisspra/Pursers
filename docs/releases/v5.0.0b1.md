# Pursers 5.0.0b1 — first GitHub beta

Pursers 5.0.0b1 is the first GitHub beta of the local-first coordination board
for AI-agent teams. It is intended for one owner on one machine and is not a
stable release.

> **Publication note:** The `v5.0.0b1` tag and GitHub release are pending.
> Remove this note when the release is published.

## What is new since 5.0.0a26

### Highlights

- AionUI Home now exposes the first-run ticket path: prepare a team, accept a
  live offer, distinguish an expired offer, and see the independently reviewed
  result ([24c007f](https://github.com/swisspra/Pursers/commit/24c007f317722d2bcfbb6b44aefb9c0822380e7e),
  [6e4b2f8](https://github.com/swisspra/Pursers/commit/6e4b2f84cd14dd3909949191245e81411925a448)).
- Offer and claim state is bound to the exact seat identity, including the
  identity carried by the offer contract
  ([6c514f8](https://github.com/swisspra/Pursers/commit/6c514f87ed39445d18d6812e0946c19ba2eca7fe)).
- Beta-path fixtures and acceptance semantics cover the normal join, status,
  Fleet, Personal, ticket, and result flow without presenting fixtures as live
  browser proof
  ([255bf1b](https://github.com/swisspra/Pursers/commit/255bf1b32e6624e5839f392eb0bd73319f84d67d),
  [304bb86](https://github.com/swisspra/Pursers/commit/304bb86c3058c71d66df4d73a216eb70757a9ae7)).
- Permanent board-join denials are bounded instead of being retried on every
  wait cycle, and live Codex seats retain their declared dispatch capabilities
  across keepalive discovery
  ([2db2f64](https://github.com/swisspra/Pursers/commit/2db2f64939828612d67862c1094333f31ff5981a),
  [bcf41e1](https://github.com/swisspra/Pursers/commit/bcf41e160eebac111156ed0fdd905d6847c9cffa)).
- Source and packaged artifacts carry Apache-2.0 licensing, the dashboard lock
  aligns with that license, and the dashboard dependency updates Hono to 4.13.7
  ([bc5c146](https://github.com/swisspra/Pursers/commit/bc5c146ed72f08042f982c445145b44b3d928ef4),
  [3fe0a43](https://github.com/swisspra/Pursers/commit/3fe0a438268b0e4b99c50b87ba607a64f09e538e),
  [5d6fbfb](https://github.com/swisspra/Pursers/commit/5d6fbfbed834ffd79cb47f046f130571e69459a3),
  [3434706](https://github.com/swisspra/Pursers/commit/3434706145cb4c0d6b0c2d27f2ba26d456024bd3)).
- Compared with the earlier reviewed candidate, rc6 fixes the Fleet dashboard
  to reuse its viewer board client so repeated `/api/fleet` requests work.

## Install and verify

Download the six wheels and `SHA256SUMS.txt` from the `v5.0.0b1` GitHub
release, then verify them before installation:

```bash
shasum -a 256 -c SHA256SUMS.txt
python3 -m pip install --no-index --find-links . \
  "pursers==5.0.0b1" "pursers-wait-bridge==0.1.0a16"
```

## Upgrading from 5.0.0a26

Freeze new intake and dispatch, back up the current profile and data, and
verify every downloaded artifact against the hashes above. Upgrade Central,
Personal, and the wait bridge in their existing environments, then fully
restart every seat and desktop host so each process reloads the new packages.
Run Fleet **Doctor** after restart and resolve identity, role, credential,
registry, version, or push-subscription drift before resuming work.

Central, Client, Personal Import, and Wait Bridge retain their a26 version
numbers in this cohort. Reinstall the exact verified wheels rather than
assuming an already-installed same-version wheel has the reviewed beta bytes.

## Known issues

### Browser201 beta boundary

Independent Browser201 verification ran against beta candidate
`dc5847395e619359f6ba06e6f8d19fd2a7ec7bd5`. The AionUi extension capture
executed all 29 observations: 23 visual assertions passed and 6 failed.
The six visual failures were:

- `extension-join.state.bridge-missing` — state copy "Install it, then retry."
  was not observed in the rc6 capture.
- `extension-join.state.error` — state copy "Join failed" was not observed in
  the rc6 capture.
- `extension-join.state.initial` — state copy "Not checked" was not observed in
  the rc6 capture.
- `extension-join.state.joining` — state copy "Joining" was not observed in the
  rc6 capture.
- `extension-join.state.status-empty` — state copy "Project not connected" was
  not observed in the rc6 capture.
- `extension.bounded-errors` — state copy "That ticket is not present in the
  bounded board response. Refresh and retry." was not observed in the rc6
  capture.

These are capture boundaries, not confirmed product defects. Evidence reference:
`CQ-3eddc8f73c6e7671`.

Only 2 observations passed the strict gate. The 6 visual failures remained
failures, and the other 21 visual passes were blocked because the required
typed-evidence records were not produced. This run therefore records a beta
boundary; it does not satisfy the complete Browser201 release gate.

Verified in this beta: the AionUi extension browser path can execute the full
29-observation visual capture at the candidate SHA, with 23 visual passes.
Not yet verified:

- Fleet dashboard acceptance. The live UI did not expose the stable board
  selectors required by the harness, so its 93 rows could not be captured.
- Personal acceptance. This build did not expose a Personal browser route on
  the AionUi origin, so its 79 rows could not be captured.
- Strict acceptance for the 21 visually passing AionUi rows that require typed
  evidence. The producer/evaluator pipeline did not supply those records.

The beta.2 follow-ups are **Fleet dashboard: expose stable board selectors the
acceptance harness requires ([data-board-id], board selection state)**,
**Personal: provide the browser route the acceptance catalogue expects
(Personal MCP App / dashboard page on the AionUi origin) or re-scope the
personal.* rows**, and **Typed-evidence pipeline: make visual passes count -
wire typed evidence for the 21 AionUi rows strict-blocked without it**.

- The supported beta boundary is one owner on one machine; remote access,
  shared untrusted machines, and multi-person boards are not supported.
- No MCP Apps host has passed the complete supported-host gate. Use agent chat
  for actions and treat the Personal dashboard as a read-only preview.
- AionUI supports pause and cooperative stop, but not resume. Recovery after an
  expired or rotated door has not completed beta acceptance.
- Several failure and empty states remain outside the beta normal-path gate,
  including all-Central outage, mixed-Central isolation, Personal search and
  lease details, and exact permission/not-found wording.
- Fleet release rows and canonical rollback-result fields remain outside the
  beta user-acceptance scope.
- The Fleet dashboard defaults to `http://127.0.0.1:8766/mcp`. When Central
  uses TLS, pass `--url https://127.0.0.1:8766/mcp` explicitly; beta.1 does not
  provide a fail-fast scheme hint. Tracked for beta.2 as “P0 fleet-dashboard:
  /api/fleet and /api/workers always 503 ExceptionGroup (httpx2.ReadError) in
  server mode against live Central”.
- Wait-bridge offer events are push-only in beta.1. A seat that misses the
  push can see only `offer_expired`; after a wait returns, call `ticket_get`
  for the pinned ticket and claim only if its current, unexpired offer belongs
  to that seat. The beta.2 fix is tracked as “wait-bridge: ticket_offered
  dropped for pinned / exclusion-fenced offers (seat sees only offer_expired)”
  and “wait-bridge offer-reconcile follow-up: keep one ticket_list per backlog
  cadence”. The beta.2 design item is “central+bridge: make offer events
  recoverable via catch-up”.
- During shutdown, Central's dispatcher background task can log
  `offer_deadline_error ... Cannot operate on a closed database`. This is log
  noise and does not affect board data. Tracked for beta.2 as “central:
  dispatcher offer-deadline task uses a closed sqlite connection
  (ProgrammingError x212 in live log)”.

See the [beta/GA split](../../planning/beta-ga-split.json) for the complete
bounded list.

personal data. Do not put sensitive security details in a public report.
