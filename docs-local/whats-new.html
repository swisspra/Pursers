Unreleased · on main

Changes after 5.0.0a22

These are not a numbered release. They are present on main and must be labelled “unreleased, on main” until a release train assigns versions and passes its gates.

Fleet-wide or dedicated seats

A blank home board serves every active registry board with boards=registry; the bridge binds to the registry board, pursers by default. A named home board is dedicated with boards=home, while its generated prompt passes boards=["<board>"]. Managed configs persist PURSERS_BOARDS and PURSERS_HOME_BOARD; seat-kit adds optional --board and --registry-board, and bin/board.sh exports PURSERS_BOARDS.

Input-safe dashboard refresh

Timer-driven panel refresh pauses while a form has focus or unsaved input. A fixed Resume pill or the status line resumes updates.

Liveness-bounded keepalive

The wait bridge renews leases only while its stdio session shows model liveness. PURSERS_KEEPALIVE_IDLE_LIMIT_S defaults to three claim TTLs; an idle pause emits lease_keepalive_paused, and keepalive-only claims are flagged in Needs attention.

Broadcast backlog recovery

Unclaimed broadcast tickets re-surface every PURSERS_BACKLOG_RESURFACE_INTERVAL_S (600 seconds by default) and are re-offered after broadcast_reoffer_s. Coordinator identities are never offered work.

Fleet clone repair

The clone endpoint populates a working tree and repairs an empty clone instead of refusing it as dirty.

Seat-kit repair

--python preserves the virtual-environment interpreter, and --upgrade no longer aborts solely on a non-fast-forward seat clone.

a21 fleet operations

Release & Operations

The loopback Config page reports tag, CI, PyPI, GitHub Release, Central version, and restart state. Destructive jobs execute only a short-lived, one-use server plan whose concrete command and digest the operator confirmed.

Fleet-owned clones

Each Registry card records fleet_clone_dir. Seat setup and Doctor require that managed clone and reject the operator checkout as a worker directory.

Live-seat dispatch

Retired and automatically stale seats leave rotation. Offers rotate across live capable seats, preserve deadlines across Central restart, and surface dispatch history in Needs attention.

Reduced tool surface

agent_nudge, board_get_briefing, and ticket_terminate are removed. ticket_assign remains admin-only, while the Personal memory_* tools remain supported for the shipped UI.

Bounded work remains subscription-first

Progress-guaranteed catch-up

Large journal windows are batched and compacted. Deadline-bounded partial results always carry a usable next cursor, and out-of-range cursors are clamped safely.

Bounded submission notes

Central caps ticket submission notes and the client exposes explicit truncation metadata instead of overrunning an MCP frame.

Exact seat ownership

Config can import seats and run Doctor for one or all. Restart checks prefer exact configured seat markers and report unknown when process ancestry cannot prove ownership.

Operator-visible failures

Stage, publish, kickstart, and restart jobs serialize conflicting work, stream bounded logs, scrub audit records, and keep rollback failures plus recovery details prominent.

  • Lifecycle: agent_retire and automatic stale retirement make retire-all-inert explicit.
  • Role defaults: board_join derives its default role from reviewer membership while still enforcing token scopes.
  • Runbook: the local fleet operations guide covers clone ownership, seat setup, Doctor, release staging, and recovery.

command = "/PATH/TO/Pursers-local/.venv/bin/python"

[mcp_servers.pursers-wait.env]

Do not set PURSERS_WAIT_MODE=push; push is already the default. Set PURSERS_WAIT_MODE=poll only while diagnosing or supporting a transport that cannot subscribe.

Reviewer seats now reserve a submitted ticket with review-claim before verification, renew that 900-second lease every five minutes, and release it automatically on approve/reject. list shows only unclaimed submissions; claim, expiry, and release are push-wait cues.

/PATH/TO/Pursers-local/bin/board.sh wait --since <cursor>

/PATH/TO/Pursers-local/bin/board.sh wait --poll --since <cursor>
The current seat-kit flag is --poll. It selects poll-only behavior; there is no --poll-only parser flag in the release.

Dashboard-first seat setup

The loopback Fleet Dashboard now provides a top-level Config page with a seat wizard, redacted diff-before-apply flow, backups, restart prompts, Doctor jobs, wait-bridge upgrades, and read-only registry coverage. Token contents stay server-side and Config writes are accepted only from loopback clients.

The wizard now declares tier, skills, work/review gates, model, and provider across Codex, Goose, Claude Desktop, and Claude Code. Connector-derived skill suggestions remain editable, Doctor flags Central drift, and each board has a dispatch panel for policy, capability gaps, current offers, and recent offer events. The wait bridge and seat kit consume these capability declarations for targeted dispatch.

Operator migration checklist

  1. Keep secrets in the host's protected configuration; use placeholders in shared documentation.
  2. Set PURSERS_ROLE explicitly to worker, reviewer, or orchestrator for every seat.
  3. Use one token identity per seat for both its wait bridge and board connector.
  4. Set fleet_clone_dir for every project in the Config page Registry card, then run seats only from that managed clone.
  5. Replace agent_nudge with Dispatcher offers, board_get_briefing with board_status / board_snapshot, and ticket_terminate with ticket_cancel. PURSERS_LEGACY_TOOLS no longer restores those removed tools.
  6. Set the correct PURSERS_HOST and configure the host timeout longer than the bridge block.
  7. Remove default-path poll settings and verify one subscription wait on a test board.
  8. Confirm timed_out=true is immediately re-armed with new_seq.
  9. Verify an idle seat performs no Central calls and a claimed seat renews only its held lease.
  10. Use PURSERS_WAIT_MODE=poll or board.sh wait --poll only as an explicit fallback.
