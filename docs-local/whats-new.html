What's new · a18 release

Workers wait for cues,
not timer polls.

The 5.0.0a18 release makes MCP 2026-07-28 subscriptions/listen the primary wait path across interactive, CLI, and headless seats.

Behavior Host profiles Seat commands Program tickets Migration

Subscription-first is the default

One long wait

The bridge subscribes to each board journal and the exact per-seat cue through BoardClient.events(). A cue triggers a bounded, side-effect-free touch=false refetch.

No idle Central loop

After the subscribe race-closing drain, an idle seat makes zero Central calls. A waiting seat with claimed tickets renews only those exact leases at the TTL-derived interval.

Explicit compatibility mode

PURSERS_WAIT_MODE=poll selects polling deliberately. A push failure is logged, degrades only that board for the current call, and push is retried on the next re-arm.

Re-arm contract unchanged

Process every result once. On timed_out=true, call wait again immediately with the returned new_seq. Never keep two waits live for one seat and board.

  • Dispatch offers: capable seats declare tier, skills, work/review flags, host, and optional model/provider at join and reconnect. A worker or reviewer now wakes only for its own offer and held-ticket lease events; reason=offer carries expiry, tier, and required skills. Legacy boards keep broadcast behavior.
  • Reviewer waits: reviewer identities now wait for submissions by default, unchanged legacy backlog cues are surfaced once per bridge process, and each return reports reason=offer|journal|backlog|timeout.
  • Orchestrator mode (TK-55b6bc8985fc): wait bridge background subscription with instant board_digest, board_digest_ack, board_watch, and board_unwatch tools for Claude Desktop leaders. Eliminates blocking wait and polling; buffers events in a persistent ring buffer, fetches with touch=false (zero board writes while idle), and emits MCP resource notifications on board://<board>/digest.
  • Tool surface audit and deprecation (TK-2ffa16368cbb): measured 7-day usage across 45 Central and bridge tools. Implemented hide-unless-legacy mechanism in Central and Wait-Bridge for a18: 10 superseded, redundant, or unused tools (agent_nudge, board_get_briefing, ticket_terminate, ticket_assign, and 6 unused memory_* tools) are hidden from default tools/list saving ~1,500 context tokens per turn (while memory_write and ticket_unclaim remain visible core tools). Seats can opt-in via capabilities={"legacy_tools": true} upon board_join or PURSERS_LEGACY_TOOLS=1 env var. Calling deprecated tools emits a _deprecated: true annotation and a one-time journal warning per caller; physical removal is scheduled for a19. Comprehensive audit documentation published at docs/tool-surface-audit.md.
  • Reviewer hardening: generated seats now carry one HARD-verify checklist, an exact-SHA board.sh verify helper, approval evidence gates, and non-empty rejection fixes. Generic leak rules ship in-repo; operator regexes load locally from ~/.pursers/leak-markers.txt or PURSERS_LEAK_MARKERS_FILE and only their count is printed.

Do not set PURSERS_WAIT_MODE=push; push is already the default. Set PURSERS_WAIT_MODE=poll only while diagnosing or supporting a transport that cannot subscribe.

Reviewer seats now reserve a submitted ticket with review-claim before verification, renew that 900-second lease every five minutes, and release it automatically on approve/reject. list shows only unclaimed submissions; claim, expiry, and release are push-wait cues.

The current seat-kit flag is --poll. It selects poll-only behavior; there is no --poll-only parser flag in the release.

Operator migration checklist

  1. Keep secrets in the host's protected configuration; use placeholders in shared documentation.
  2. Set PURSERS_ROLE explicitly to worker, reviewer, or orchestrator for every seat.
  3. Use one token identity per seat for both its wait bridge and board connector.
  4. Set PURSERS_LEGACY_TOOLS=1 only while deprecated tools are required; this compatibility path is removed in a19.
  5. Set the correct PURSERS_HOST and configure the host timeout longer than the bridge block.
  6. Remove default-path poll settings and verify one subscription wait on a test board.
  7. Confirm timed_out=true is immediately re-armed with new_seq.
  8. Verify an idle seat performs no Central calls and a claimed seat renews only its held lease.
  9. Use PURSERS_WAIT_MODE=poll or board.sh wait --poll only as an explicit fallback.
