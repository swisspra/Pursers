หน่วยความจำเอเจนต์ 4 ชั้น

วิธีจัดหน่วยความจำถาวรให้เอเจนต์เขียนโค้ดบนเครื่องเดียว — อะไรโหลดอัตโนมัติ อะไรรอให้เรียกอ่าน และอะไรที่ไม่ออกจากเครื่องเลย

4 ชั้น2 โดเมนแยกขาดPursers 5.0.0a21ซิงก์เฉพาะส่วนที่ปลอดภัยlocal-first

ทั้งระบบหมุนรอบสมดุลเดียว ทุก session จะมีข้อความก้อนหนึ่งถูกโหลดเข้ามาอัตโนมัติ — ใส่น้อยไป ชั้นลึกก็ไม่มีใครไปถึง เอเจนต์ไม่รู้ว่ามีอยู่ คลังก็ตายทั้งที่ยังไม่ถูกอ่าน ใส่มากไป ทุก session ก็เริ่มต้นด้วยความอ้วน แล้วตายด้วยค่า context แทน

ไฟล์ที่โหลดอัตโนมัติจึงถือเฉพาะกฎเหล็ก แนวทางการทำงาน และป้ายบอกทาง ส่วนข้อเท็จจริงก้อนใหญ่อยู่ชั้นถัดลงไป และถูกอ่านตอนที่งานทำให้มันเกี่ยวข้องเท่านั้น

ภาพรวมทั้งสี่ชั้น

ชั้น 2

ชั้น 3

ชั้น 4
ซิงก์git allowlist ที่เก็บเฉพาะส่วนที่พกพาได้ และไม่แตะอย่างอื่นเลย

ชั้น 1 — ตัวฉีด

ไฟล์เดียวที่การันตีว่าอยู่ใน context เสมอ ที่เหลือต้องพิสูจน์ตัวเองก่อนถึงจะได้เข้า

โหลด
ทุกครั้ง

เล็กโดยเจตนา ไม่ใช่เพราะยังเขียนไม่เสร็จ

~/.claude/CLAUDE.md

ไฟล์นี้ถูกมองเป็นชั้นของ system prompt ไม่ใช่ฐานความรู้ มันถือแค่สี่อย่าง และปฏิเสธที่เหลือทั้งหมด:

  • กฎเหล็กที่ปักหมุดไว้ — เส้นที่ห้ามข้ามไม่ว่ากรณีใด
  • แนวทางการทำงาน — ความกระชับ นิสัยการตรวจสอบ เมื่อไหร่ควรถามแทนเดา
  • บริบทของบัญชี — ตัวตนไหนใช้กับงานประเภทไหน
  • ป้ายบอกทาง — ข้อเท็จจริงจริง ๆ อยู่ที่ไหน เพื่อให้เอเจนต์รู้ว่าต้องไปดู

กฎง่าย ๆ: ถ้าข้อเท็จจริงนั้นจำเป็นแค่กับงานบางประเภท มันอยู่ในคลังชั้น 2 ไม่ใช่ที่นี่

ความจำถาวร เรียงตามความคงทน และตามโดเมนที่มันสังกัด

สี่ tier แหล่งความจริงเดียว

~/.claude/memory/

0-core/       L0   หลักการ กฎเหล็ก นโยบาย ข้อเท็จจริงถาวร
                  แหล่งความจริง — ปลดระวาง/รีเฟรชข้อเท็จจริงได้
1-main/       L1   ความจำใช้งานราย session — ที่ที่การกลั่นกรองลงมาพัก
2-work/       L2.1 โดเมนงานอาชีพ
2-personal/   L2.2 ทุกอย่างนอกเหนือจากนั้น

ไฟล์ดัชนีใน 0-core/ คือประตูทางเข้า — สารบัญบรรทัดเดียวต่อข้อเท็จจริง จัดกลุ่มไว้ ชี้ไปทุกไฟล์ในคลัง มันคือสิ่งที่เอเจนต์กวาดตาดูเมื่อป้ายบอกทางในชั้น 1 ส่งมันมาที่นี่

การแยกขาด — ห้ามข้ามเด็ดขาด

สอง tier โดเมนไม่ปะปนกัน: ไม่ใช่ข้อมูล ไม่ใช่ความจำ ไม่ใช่บริบท ไม่ใช่ผลงาน เครื่องมือหรือบัญชีที่อนุญาตให้ใช้กับโดเมนหนึ่ง จะไม่ถูกใช้กับอีกโดเมนหนึ่ง นี่คือกฎข้อเดียวที่ตัวฉีดยอมเสียพื้นที่อันจำกัดของมันเพื่อเขียนซ้ำแบบเต็ม ๆ เพราะการละเมิดตรงนี้แก้ด้วยการตามเก็บกวาดทีหลังไม่ได้

การเลื่อนขั้นวิ่งขึ้นข้างบนพร้อมการทบทวน: สิ่งที่เรียนรู้ระหว่าง session จะพักอยู่ใน 1-main/ จนกว่าจะพิสูจน์ว่าคงทน แล้วจึงย้ายเข้า 0-core/ ในฐานะข้อเท็จจริง

ชั้น 3 — memory ต่อโปรเจกต์

ข้อเท็จจริงที่มีความหมายเฉพาะในโฟลเดอร์เดียว เก็บไว้ข้าง ๆ ประวัติ session ของโปรเจกต์นั้น

ผูกกับ
โฟลเดอร์

หนึ่งไฟล์ หนึ่งข้อเท็จจริง หนึ่งดัชนี

~/.claude/projects/<project-key>/memory/

project key คือ path ของโฟลเดอร์ที่ทำงานอยู่ โดยแทนอักขระที่ไม่ใช่ตัวเลขหรือตัวอักษรทั้งหมดด้วยขีด — โฟลเดอร์เดิมจึงชี้ไปที่ความจำเดิมเสมอ และโฟลเดอร์ที่ถูกย้ายหรือเปลี่ยนชื่อจะได้ความจำชุดใหม่

แต่ละความจำเป็นไฟล์ markdown ไฟล์เดียว มี frontmatter สั้น ๆ กำกับ:

---
name: สลักสั้น ๆ
description: หนึ่งบรรทัด — ใช้ตัดสินความเกี่ยวข้องตอนเรียกคืน
type: user | feedback | project | reference
---

ตัวข้อเท็จจริง สำหรับ feedback และ project ตามด้วย:
**Why:**            เหตุผลที่ทำให้มันติดหัว
**How to apply:**   แล้วต้องทำอะไรต่างไปจากเดิม

สี่ type แบ่งพื้นที่ได้ครบโดยไม่ทับกัน: user คือผู้ใช้เป็นใคร feedback คือคำแนะนำที่เขาเคยให้ project คืองานที่กำลังทำซึ่งอ่านจากโค้ดไม่ได้ และ reference คือป้ายชี้ไปยังแหล่งภายนอก

ไฟล์เชื่อมถึงกันด้วยลิงก์วงเล็บเหลี่ยมคู่ ลิงก์ไปยังความจำที่ยังไม่มีอยู่ถือว่าปกติ — มันคือหมุดว่ามีเรื่องควรเขียนเพิ่ม ไม่ใช่ลิงก์เสีย

สิ่งที่ตั้งใจ ไม่ เก็บที่นี่: อะไรก็ตามที่ repo บันทึกไว้อยู่แล้ว — โครงสร้างโค้ด การแก้บั๊กที่ผ่านมา ประวัติ commit หรือไฟล์คำสั่งของโปรเจกต์เอง

ลำดับอำนาจที่ไม่ต้องเดา

แต่ละชั้นตอบคำถามที่แคบกว่าชั้นเหนือมัน และถูกอ่านตามลำดับนั้น คำแนะนำสองอันที่ขัดกันจึงมีผู้ชนะที่ตายตัวเสมอ เอเจนต์ไม่ต้องเลือกเอาเอง

ที่ 1
กฎเหล็กเด็ดขาด ไม่มีชั้นล่างใดผ่อนปรนได้
ที่ 2
แนวทางการทำงานจะเดินยังไงในพื้นที่ที่กฎเหล็กเปิดช่องไว้
ที่ 3
memory ของโปรเจกต์ชนะข้อเท็จจริงทั่วไป เมื่ออยู่ในโฟลเดอร์ของตัวเอง
ที่ 4
ข้อเท็จจริงของโดเมนใช้เมื่อไม่มีอะไรที่เจาะจงกว่าพูดถึงเรื่องนั้น

ตัวหนังสือถูกเขียนให้ตรงกับลำดับชั้นด้วย ตัวฉีดใช้ประโยคสั่ง — เป็นกฎ ไฟล์ใน tier ใช้ประโยคบอกเล่า — เป็นข้อเท็จจริงที่ลงวันที่และถอนได้ ส่วน memory ของโปรเจกต์ใช้ประโยคแก้ — ที่นี่ต้องทำต่างไปยังไง และเพราะอะไร น้ำเสียงของไฟล์บอกอำนาจของมันตั้งแต่ก่อนอ่านเนื้อหา

นี่คือเหตุผลที่คลังยึดกติกาหนึ่งไฟล์ต่อหนึ่งข้อเท็จจริงด้วย ไฟล์ที่เถียงสองเรื่องพร้อมกันจะถูกจัดอันดับ ปลดระวาง หรือรีเฟรชอย่างสะอาดไม่ได้ แถมยังบังคับให้คนอ่านต้องโหลดทั้งสองเรื่องเพื่อใช้เรื่องเดียว

การโหลด

prefix ที่นิ่ง คือ session ที่ถูก

คุณสมบัติสามข้อของโครงสร้างนี้ ตกผลึกมาจากข้อจำกัดเรื่อง prefix โดยตรง:

  • ตัวฉีดเล็กและแทบไม่ขยับ — กฎเหล็กกับแนวทางการทำงานเปลี่ยนกันเป็นเดือน prefix จึงเหมือนเดิมทุกไบต์ และ session เปิดมาด้วยการอ่านแคช ไม่ใช่เขียนใหม่
  • ข้อเท็จจริงมาทีหลัง ในฐานะผลลัพธ์ — การอ่านไฟล์ tier กลาง session คือการต่อท้ายบทสนทนา ไม่ใช่การเขียนหัวคำขอใหม่ การเรียกความจำจึง ต่อ แคช ไม่ใช่ทุบมัน
  • โตแบบต่อท้าย — ความจำใหม่คือไฟล์ใหม่บวกดัชนีอีกหนึ่งบรรทัด ไม่มีอะไรที่นั่งอยู่ใน prefix แล้วถูกเขียนทับ แคชของเมื่อวานจึงยังตรงกับวันนี้

ความไม่สมมาตรของราคาคือเหตุผลที่คุ้มจะออกแบบรับ: การอ่านแคชคิดราวหนึ่งในสิบของอัตรา input ปกติ ขณะที่การเขียนแคชคิดแพงกว่าอัตราปกติ การทำแคชเสียจึงไม่ใช่เสมอตัว แต่คือการจ่ายเต็มราคาซ้ำ สำหรับข้อความที่ซื้อไปแล้ว

ผลตอบแทนทั้งสองอย่างมาจากคุณสมบัติเดียวกัน การแยกนโยบายที่คงทน ออกจากข้อเท็จจริงที่ผันผวน คือสิ่งที่ทำให้ลำดับอำนาจตายตัว และเป็นสิ่งเดียวกันที่ทำให้หัวของคำขอนิ่งพอจะแคชได้
